# Release process

Releases are cut from a clean `main` with a green CI run. **Releases never
deploy to a production server** (task book 18.4).

## Preconditions

1. `./gradlew clean build` passes on JDK 21.
2. `docs/version-matrix.md` has no `UNRESOLVED` entry for the target build.
   An unresolved Purpur build is a hard release blocker.
3. No secret, real log, player data or world file in the tree
   (`.gitignore` + secret scanning).
4. `CHANGELOG.md` updated; breaking `sky-api` changes have a migration note in
   `docs/migration.md` and at least one deprecation cycle.

## Steps

```bash
# 1. verify
./gradlew clean build javadoc

# 2. tag (annotated, signed where a signing key is available)
git tag -a v0.1.0 -m "release: 0.1.0"
git push origin v0.1.0

# 3. the release workflow builds artefacts, generates SHA-256 checksums
#    and attaches them to the GitHub Release
```

## Artefact policy

- Every published artefact is accompanied by its SHA-256 checksum.
- Build provenance is generated by CI where the runner supports it.
- Floating `latest` versions and unpinned SNAPSHOT coordinates are forbidden
  for production releases (task book 2.1).
- A release that promises a TPS figure must link to the reproducible
  baseline/shadow/protect report in `docs/benchmark.md`.
